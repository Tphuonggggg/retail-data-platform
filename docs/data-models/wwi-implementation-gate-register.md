Owners là responsibilities, không tạo accounts/delegate authority mới: **SO** Source Owner/DBA; **IN** ingestion implementer; **ST** storage implementer/custodian; **DW** warehouse/dbt implementer; **DQ** validation reviewer; **INF** infrastructure; **OP** operator/orchestration; **AO** analytics/consumer owner; **PO** Project Owner approval authority. D3: DQ detects/collects/recommends, PO authorizes lifecycle, OP executes approved transition/audit. No current account/profile/RBAC verification trong DW-04.

### Checkpoint classes — không yêu cầu mọi runtime gate trước viết code

| Class | Acceptance boundary | Earliest checkpoint |
| --- | --- | --- |
| A | Required authorization/technical prerequisites trước bắt đầu applicable implementation task/operation | PO task/phase/dependency authority; M1/M2 approvals trước provisioning/schema/dependency changes |
| B | Before accepting physical full Raw ingestion/normal Raw publication | M2 mapping approval; M3 full extraction proof; M4 durable/reconciled publish |
| C | Before publishing incremental results | M7 consistency/window/full-state/replay/checkpoint/sandbox tests |
| D | Before accepting SCD2/Facts/Core output | M5 minimum registry/lookup/header/grain/R-U-I; M8 changed-state/restatement/restore cases before use |
| E | Before Certified analytical publication/consumption/lifecycle action | M6 selected view/bundle complete population, B5 values/AP gates/consumer pins; joint proof and D3 action authorization |

A chưa đạt không được thực hiện operation tương ứng. B/C/D/E là **release/use gates**; design/code/unit work có thể được giao trước runtime execution nếu dependencies/approval rõ, không vì test chưa chạy mà gọi architecture incomplete. Không defer basic Raw atomicity/precision/reconciliation tới M9/monitoring. Conditional feature gate applies only before feature use, không buộc optional B/C mart optimization để nghiệm thu baseline A.
